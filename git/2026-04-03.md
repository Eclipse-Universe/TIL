# [TIL] 2026-04-03: 문서 분류 모델 최적화 - 앙상블의 한계와 2-Stage 분류기로의 선회

## 🎯 오늘 목표
- 기존 최고 점수(0.9702)의 벽을 뚫기 위한 모델 성능 개선
- 점수 폭락(0.84)의 원인 분석 및 데이터 구조(EDA) 재확인

## 🛠 진행 내용 및 결과

### 1. EDA를 통한 뼈아픈 팩트 체크
- **문제점:** 이전 후처리(규칙 기반 크롭 & 하드 보팅)로 점수가 폭락했던 원인을 시각화로 찾아냄.
- **발견:** Class 13은 '소견서'가 아닌 '이력서'였으며 상단에 제목이 없는 표 형태였음. 문서 상단을 잘라 특정 텍스트를 찾는 하드 코딩 방식이 완전히 틀렸음을 인지.

### 2. 3-Way Mega Ensemble 시도
- **가설:** CNN(EfficientNet-B4, ConvNeXt-Base)이 보지 못하는 전역적 맥락(Global Context)을 잡기 위해 Transformer 계열인 `MaxViT`를 3번째 모델로 투입.
- **과정:** - MaxViT 단일 모델 5-Fold 학습 진행 (단일 OOF F1: 0.950 달성).
  - 3개 모델 × 5-Fold × 8 TTA = 총 120개 예측의 Soft Voting 앙상블 파이프라인 구축.
- **결과:** Public Score **0.9436**. (기존 0.9702 대비 하락) 
- **인사이트:** 아무리 강력한 ViT 모델을 추가해도, 단순히 모델의 머릿수만 늘리는 '무지성 앙상블'로는 미세 분류(Fine-grained)의 병목을 뚫을 수 없음을 확인.

### 3. 대회 룰 재확인 (Risk Management)
- **교훈:** Test 셋의 예측 결과를 학습에 끌어다 쓰는 Pseudo-Labeling을 시도하려 했으나, "평가 데이터 학습 활용 금지" 룰을 뒤늦게 인지함. 어떤 강력한 기법이라도 대회 규정(Boundary) 안에서 유효한지 검증하는 것이 최우선임을 다시금 깨달음.

### 4. 오답 분포 분석 (Confusion Matrix)
- **과정:** 무작정 모델을 바꾸는 대신, 기존 0.9702 베이스라인 모델이 "정확히 어디서 틀리고 있는지"를 추적하는 에러 분석기(`analyze_errors.py`) 작성 및 실행.
- **발견:** 오답이 무작위로 발생하는 것이 아니라, **특정 의료/증명서 그룹(Class 3, 4, 7, 14) 내부에서 심각한 혼동(Confusion Family)**이 발생하고 있음을 데이터(오답 카운트)로 증명.

## 🚀 다음 액션 플랜 (Next Step)
모델 아키텍처나 하이퍼파라미터 튜닝은 전면 중단하고, 철저히 **"데이터와 오답의 특성"**을 타겟팅하는 방향으로 전략 선회.

1. **2-Stage Sub-Classifier 도입**
   - 1차: 기존 메가 앙상블로 분류.
   - 2차: `[3, 4, 7, 14]` 등 혼동 그룹으로 예측된 데이터만 보류(Hold)시킨 뒤, 해당 클래스들의 미세한 차이(서식, 도장 등)만 학습한 **소분류 전용 저격수 모델**에 태워 최종 정답을 확정.
2. **Targeted Augmentation**
   - Test 데이터의 실제 훼손 상태(노이즈, 회전 등)와 유사한 환경을 Train 데이터에 부여하여 해당 혼동 그룹의 판단력을 끌어올리기.
